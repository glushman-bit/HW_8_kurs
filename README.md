### Ветка 33
 - Реализован сервис автоматической фоновой рассылки уведомлений для подписчиков курсов. При создании/редактировании уроков или обновлении самого курса подписчикам отправляется пакетное email-уведомление. Для предотвращения спама установлена защита: уведомления отправляются, только если материалы курса не обновлялись последние 4 часа.
 - Для работы фоновых задач на вашем компьютере или сервере должен быть запущен **Redis** в качестве брокера сообщений.
 - Параметры для настройки окружения (`.env`) можно посмотреть в файле `.env.example`
 - Для полноценного тестирования функционала необходимо запустить три параллельных процесса в разных терминалах.
 - Запустите фоновый процесс Celery для обработки задач рассылки. 

Для Linux / macOS:
  ```
  celery -A config worker -l info
  ```
Для Windows (требуется библиотека eventlet):
  ```
  pip install eventlet
  celery -A config worker -l info -P eventlet
  ```
(Примечание: Замените `config` на имя папки вашего проекта, где находится файл `celery.py`, если оно отличается).

 - Логика работы сервиса:
1. *Выборка пользователей:* Запрос оптимизирован с помощью `.values_list('user__email', flat=True)`, из базы извлекаются только email-адреса и только для активных пользователей (`user__is_active=True`), подписанных на конкретный курс.
2. *Батч-обновление в БД:* Фиксация времени отправки происходит пакетно с помощью `.update(updated_at=now)` напрямую в базу данных, минуя тяжелый метод `save()`.
3. *Пакетная отправка писем:* Отправка писем реализована через встроенный метод Django `send_mass_mail`. Все письма уходят за одно SMTP-соединение, при этом каждый подписчик получает индивидуальное письмо (чужие адреса в поле «Кому» скрыты).

 - Реализована периодическая фоновая задача для автоматического контроля активности пользователей. Система раз в сутки проверяет базу данных и деактивирует аккаунты пользователей, которые не проявляли активность на сайте более 30 дней.
 - Запустить автоматический планировщик задач:

Запуск Celery Worker
В первом окне терминала запустите воркер, который будет выполнять команды блокировки:
```
celery -A config worker -l info
```

Запуск Celery Beat (Планировщик)
Во втором окне терминала запустите планировщик, который будет отправлять задачи воркеру строго по расписанию:
```
celery -A config beat -l info
```

### Docker и Deploy (ветка 35.2)

#### Docker

Проект контейнеризирован с использованием Docker.

Используется:

- Dockerfile для сборки образа приложения
- Docker Compose для запуска всех сервисов
- Docker Hub для хранения Docker image
- GitHub Actions для автоматической сборки и деплоя

#### Dockerfile

Dockerfile находится в корне проекта.

Он выполняет:

1. Создание контейнера на основе Python 3.14
2. Установку системных зависимостей
3. Установку зависимостей Python через Poetry
4. Копирование проекта внутрь контейнера
5. Подготовку окружения для запуска Django


Сборка образа вручную:

```
docker build -t project_name .
```

#### Docker Compose

Файл: docker-compose.yml
Используется для запуска полного окружения проекта.

Сервисы:

| Сервис        | Назначение                  |
|:--------------|:----------------------------|
| web           | Django + Gunicorn           |   
| db            | PostgresSQL                 |   
| redis         | Redis брокер для Celery     |
| celery        | Выполнение фоновых задач    |
| celery-beat   | Планировщик задач           |
| nginx         | Reverse pro                 |
|               |                             


#### Запуск проекта

Сборка и запуск:
```
docker compose up --build
```
Запуск в фоне:
```
docker compose up -d
```
Остановка:
```
docker compose down
```
Проверка контейнеров:
```
docker compose ps
```

#### Переменные окружения

Используется файл: .env
```
.env.example:

POSTGRES_DB=my_database
POSTGRES_USER=postgres
POSTGRES_PASSWORD=password

POSTGRES_HOST=db
POSTGRES_PORT=5432

REDIS_HOST=redis
REDIS_PORT=6379

CELERY_BROKER_URL=redis://redis:6379/0
CELERY_RESULT_BACKEND=redis://redis:6379/0
```

#### Celery

Celery использует Redis как брокер сообщений.

Worker запускается командой:
```
celery -A config worker -l INFO
```
Beat запускается:
```
celery -A config beat -l INFO
```
Проверка логов:
```
docker compose logs -f celery
docker compose logs -f celery-beat
```

#### Nginx

Nginx используется как reverse proxy.

Схема работы:
```
Пользователь
      |
      v
   Nginx :80
      |
      v
 Gunicorn :8000
      |
      v
 Django
```
Конфигурация находится:
```
nginx/nginx.conf
```
Основная задача Nginx:

 - принимать внешние HTTP-запросы;
 - передавать их Django;
 - отдавать статические файлы.

Проверка конфигурации:
```
docker compose exec nginx nginx -t
```

#### Gunicorn

Django запускается через Gunicorn:
```
gunicorn config.wsgi:application --bind 0.0.0.0:8000
```
Gunicorn работает внутри контейнера web.

#### Deploy на сервер

Автоматический деплой выполняется через GitHub Actions.

Workflow:
```
.github/workflows/django.yml
```
После успешного прохождения:

 - Проверка кода (flake8)
 - Запуск тестов
 - Сборка Docker image
 - Отправка image в Docker Hub
 - Подключение к серверу по SSH
 - Обновление контейнеров

#### GitHub Secrets

SSH_KEY

DOCKER_HUB_USERNAME
